# 原生执行与重算校验分阶段

R7检查点a1bc642b保留并发控制负结果：4B的32对输出/context通过，但2s窗口内无其他Session完成或开始，且采样依赖完成回调而缺失。Session-1第8轮的原生/完整重算请求均在窗口前5ms开始、窗口后6.421s结束。不能据此把无对照的Agent执行说成被工具阻塞。

本轮保留`concurrent`协议，并新增显式`after-run-serial`控制时序：先以真实原生Session完成固定双会话16轮及2s受控工具；记录真实执行阶段边界，观察SessionIdle持页并关闭释放后，逐条完整原始历史重算。全部32对输出仍必须逐ID一致，任何分叉保留并失败。比较的是验证时序，不能把移出窗口的校验计算称为系统总计算量减少或性能加速。

工具期间启动独立的异步指标采样任务，按协议明确的0.1s间隔采集六个计数，结束时停止并等待；采样不再依赖另一请求完成。缺失/错误继续失败，保留时间戳，仅落盘JSON支持的计数。两种时序及采样间隔为显式必填行为参数，无隐式默认。

两个新协议文件只改变控制时序、采样参数及scope说明；系统/用户文本、filler、Session数、16轮、8输出、工具位置/2s等待/求和参数与原R7一致，原26cd9cf6 workload保持原字节。原负点不改称通过。新旧完整原始token轨迹另行比较，不能由文本相同假定动态生成历史逐ID相同。

软件先覆盖两种时序、无控制并发的阶段边界、真实指标JSON、失败保留/关闭清理、参数拒绝及新旧输入配置相同。完整格式检查后固定新清单并服务器逐项匹配，先4B串行实测，再依结果扩展四模型。任何独立性能对比仍需另外固定协议/重复，当前验证时延不作加速结论。无生产调度器、WAITING_TOOL枚举或模型计算改动。
