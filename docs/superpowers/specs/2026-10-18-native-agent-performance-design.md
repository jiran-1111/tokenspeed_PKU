# 固定原生Agent轨迹的独立性能比较

R8四模型质量/工具等待验证已发布769d4bb8，128配对通过；额外并发控制点也通过，不能把旧R7失败只归因于并发质量重算。下一问题是Session复用本身的延迟、吞吐和资源差异，必须使用独立ON/OFF性能臂。

方案比较：把质量控制并发混入测量会改变竞争负载，放弃；每臂重新冷启动引擎可隔离进程状态但混入加载/编译成本；选择同一配置/引擎内独立执行两臂，双方完整轨迹预热一次，正式三轮顺序ON/OFF、OFF/ON、ON/OFF，保留次序/预热局限，不作统计显著性或通用最优结论。

输入为各模型已公开R8全部32条真实完整历史/suffix/output IDs及其SHA。两会话16轮、8输出，Session-0第8轮前执行原受控2秒求和。ON只发增量、OFF逐轮全历史，模型实际输出须逐ID等于固定轨迹；不注入输出，不在分叉后继续强制轨迹。明确是已验证真实轨迹的条件重放，不是新的自主工具选择。每臂并发两会话，正式每模型6臂192请求；双方预热64请求另列不入统计。

逐请求记录单调时钟TTFT/E2E/8输出，TPOT=(E2E−TTFT)/7标为客户端流近似。wall从并发工作提交至全部流完成，含2s工具等待、排除Session创建/关闭及采样停止；吞吐=实际输出256/wall，不解释为NPU利用率。ON检查current-frontier元数据，失败先drain提交流、关闭Session，再落盘失败；每臂结束引擎仍存活时确认active归零。

独立Prometheus采样只记六个JSON安全gauge。npu-smi按1秒等待周期采样目标card1每chip的used/capacity MB，保存原表、查询耗时、时间戳和phase；严格辨认设备统计行而非进程行。只称观察峰值，非瞬时峰值/KV专属量。线程必须在Engine.shutdown前stop并join，任何采样/解析失败使运行失败，保留原始记录。
