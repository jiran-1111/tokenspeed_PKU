# 首次控制查询回复循环修复

已发布R5候选保持固定，后续在独立分支`course/agent-20261017`上执行。实际R5 NPU采集曾在任何generate前调用get_server_info挂起；普通生成路径启动回复循环后可完成查询。源码表明get_internal_state及set_internal_state直接等待communicator，遗漏其他控制接口一致使用的auto_create_handle_loop。

选择在这两个入口发送请求前启动已有回复循环。相比由每位调用者先生成一次的规避方式，这恢复原有控制API首调契约；相比在所有communicator内部改变生命周期，修改范围仅两个同类入口，不改变统一调度/计算路径，也不新增后台循环类型或超时默认值。

先以实际入口方法和受控异步回复队列测试首调及重复调用：没有消费者则有界超时，启动消费者后返回多rank结果，测试结束取消自身任务。getter及setter分别覆盖，不检查实现行数。通过后补两处既有启动调用。

软件验证须完整course回归，最终格式后生成新源码清单、服务器逐项匹配。实际NPU验证串行、先查映射及空闲，启动0.8B图模式Engine后在首次generate前完成get_server_info，再正常生成；调用进程外置超时仅用于实验防挂，不修改生产API语义。原挂起日志保留。新的源码结果单独记录，不把R5性能冒充新版本测量。

本修复是后续Agent观测工作的前置缺陷修复，不代表多轮、工具等待、TP或最终项目验收。全部实际实现和验证由AI工具辅助执行。
