## 当前结论

本轮已补足从原 checkpoint/IDs 自行传播 hidden、FA KV、GDN conv/FP32 SSM 的独立完整 CPU 参考，并在两种 TP 分片和两种存储策略下完成原 4B/9B 固定轨迹。FP32 control 的 TP1/TP2 及其与独立完整 HF CPU 参考的接近，支持此次实现的模型公式、分片组装和续接关系在这两条轨迹上自洽。独立 BF16 传播复现了 9B 的末步选择分叉，也暴露了 4B 参考末步精确并列最大值。

这些结果仍不足以证明原部署全部数值可接受。engine/ref 的完整向量、规范化边界和状态中保留明显非零差异；原 canonical argmax 计数、原 greedy 失败与既有验收条件不得被最大集合诊断或 FP32 control 替代。此次复核未发现需要修改冻结参考/比较算法的具体数值错误；原部署与声明 CPU 数学参考之间的大差异尚未得到完整的定量解释。

## 9B：复现选择分叉与大残差同时存在

9B 独立 BF16 ref1 最后唯一选择 25389，ref2 最后唯一选择 35378；engine1/ref1 和 engine2/ref2 各有 **10/10** 个 canonical argmax 一致。FP32 control1/control2 以及完整 HF CPU FP32 的最后选择均为 25389。

末步两候选的具体分数：

| 路径 | 25389 | 35378 | 最终 argmax |
| --- | ---: | ---: | ---: |
| engine1 | 16.38751602 | 13.62465477 | 25389 |
| BF16 ref1 | 16.74917412 | 13.43647671 | 25389 |
| engine2 | 17.24241638 | 17.39577103 | 35378 |
| BF16 ref2 | 17.45204163 | 17.54627419 | 35378 |

因此，独立 checkpoint/IDs 传播和声明 BF16 分片存储能够在不执行 NPU/HCCL 的路径中产生相同的末步选择分叉；不能仅凭这一次选择分叉就把原因定位为集合通信或切片错误。这也没有排除原部署存在额外实现/算术问题，或证明所有差异都已由分片存储定量解释。

**0.3268153420 发生在 step8，并非末 step9。** 独立从归档 logits 重新计算 step8：engine2/ref2 的相对 L2 为 `0.3268153420039958`、最大绝对差 `10.691302299499512`，两侧仍都选 2649。末 step9 相对 L2 为 `0.09698174488600246`，最大绝对差 `2.9217692613601685`，两侧都选 35378。argmax 只约束哪个分量最大；大量其他分量和最大值的间隔仍可改变，因此 10/10 选择一致与大向量残差并不矛盾。

这不是仅输出选择层面的差异：服务器比较记录的末步 final norm 相对 L2，engine2/ref2 为 `0.19560915137594276`；最终 GDN conv history 中 TP2 rank1 layer22 的相对 L2 为 `0.4225432663982067`。这些上游状态差异应继续保留，不能因最终 token 相同而忽略。

## 4B：精确并列只提供有限诊断

独立读取归档最后的完整 248320 维向量，确认两条 BF16 参考的精确最大集合都恰为 **{198,271}**，两值均为 **21.25**，没有第三个并列最大元素。NumPy canonical argmax 取 198。因此原比较计数仍为 engine1/ref1 **18/18**、engine2/ref2 **17/18**。

| 路径 | 198 | 271 | 精确最大集合 |
| --- | ---: | ---: | --- |
| engine1 | 21.125 | 21.125 | {198,271} |
| engine2 | 21.125 | 21.25 | {271} |
| BF16 ref1 | 21.25 | 21.25 | {198,271} |
| BF16 ref2 | 21.25 | 21.25 | {198,271} |
| FP32 control1 | 21.14126205 | 21.16382027 | {271} |
| FP32 control2 | 21.14126587 | 21.16382027 | {271} |
| 完整 HF CPU FP32 | 21.14125252 | 21.16379547 | {271} |

engine2 的 271 确实属于参考的**零 epsilon 精确最大集合**；逐步检查该集合诊断时，engine1/ref1 与 engine2/ref2 都为 18/18。它说明 BF16 参考在末步已无法给两候选排出唯一优劣，而实际选择仍落在参考最大集合中。

但 engine2 自身两分数不等，271 是其唯一最大值，故不能把这次 mismatch 全部改写为“只是采用不同 tie-break 规则”。实际 logits 已有变化；末步 engine2/ref2 相对 L2 仍为 `0.02019623697501571`、最大绝对差 `0.30859375`，整条轨迹最大相对 L2 仍为 `0.1648125441`。原 17/18 canonical 计数和所有向量差异必须保留。最大集合检查只能作为补充诊断，不是新验收 gate。

## 最早边界与可解释范围

初始 embedding 在两模型、两种 TP 的全部实际 rank 上与 checkpoint 投影逐值相等。4B 的第一 input norm 也与 BF16 参考逐值相等；其最早非零 norm 边界为 layer0 post-attention 的 Prefill，全行相对 L2 为 TP1 `0.0003560600`、TP2 `0.0003878309`。9B 在第一 input norm 的 524288 个 Prefill 元素中已有 6 个不同，最大绝对差 `0.00390625`，相对 L2 `1.2343198e-5`，两种 TP 相同。

这些位置能排除“所有差异最初只出在最后输出头”的叙述，并给出明确的首个观察边界；它们尚不能证明后续所有误差均由这些最初差异因果决定，也不能把某个 chunk scan、归约或有限 exp 的影响量自动解释为最终大残差。对未仿真的 NPU 内部细节仍应保持声明边界，不增加适配结果的精度候选或验收容差。
