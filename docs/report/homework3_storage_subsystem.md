## 恢复边界与设备块复用

Attention K/V 按 128-token 前缀保存。递归与卷积状态保存已物化的 Prefill 检查点，恢复时通过既有联合前缀匹配选择所有组都完整的边界。活动请求和传输中的块由现有引用及完成事件保护。写出按前向流完成顺序执行，重新分配后的清零和计算等待 D2H 读完旧数据。TP=2 在各 rank 完成事件求交后推进调度状态。Host 未命中使用保留的原始 token 历史重算。

4B 大预算高复用的首个续轮，从上下文位置 768 恢复，旧历史长度为 776，旧已计算边界为 775，新输入总长为 786。因此重算旧已计算区间 `[768,775)` 的 7 token，再计算上一轮末尾尚未前向的采样 token 和本轮后缀。所有重算均包含在续轮端到端延迟中。逐轮范围保存在 `acceptance.json`。

两个 rank 都记录到 `full_attention` 的块 31 从会话 0 分配给会话 1。该时刻有 5 个活动物理块和 7 个空物理块，证明回收空间进入后续会话的实际分配。HBM 使用预分配池，监控总占用保持相近，回收收益由块表和恢复命中体现。

## 实验条件与时延／吞吐

两模型均为 BF16、TP=2、eager、512-token Prefill 分块、2048 最大上下文、固定设备缓存配置、最多一个执行请求。三条会话交替运行四轮，每轮输出 8 token。高复用续写同三条会话，低复用每轮建立三个新会话。Off 与 On 均开启设备前缀缓存，唯一功能变量为 Host 卸载及其预算。参考执行另起引擎并关闭前缀与 Host 缓存。

本次经用户授权在逻辑设备 6/7、物理 NPU 3 上共享串行运行。每格结束后再启动下一格，保存常驻服务和进程记录。预热为首轮，延迟中位数来自其后九轮。请求输出率按这九轮输出 token 除以请求耗时总和，整段输出率按十二轮输出除以含预热、开关会话及设备采样的工作负载墙钟时间。

高复用大预算的恢复请求延迟包含 H2D、检查点之后的重算和本轮生成。九次 Host 命中的 H2D 事件累计耗时，0.8B 在 rank 0 和 rank 1 上分别为 38.73 和 37.82 ms，4B 分别为 53.49 和 49.70 ms。单独的 H2D 事件时间不包含完整恢复请求的重算与生成时间。

0.8B 各组共享芯片总 HBM 峰值范围为 8047–8583 MiB，4B 为 11874–12400 MiB。数值包含常驻服务。Off/On 保持相同设备池，大预算下每个 rank 至少有 37 个 CacheBlock 在不同会话间重新分配。具体逐芯片峰值及原始监控见证据，不能把共享总量当作单引擎分配量。

本次 Off 能通过丢弃并重算容纳相同访问序列，因而两边均可进行延迟对照。大 Host 预算保住三会话检查点，能减少高复用续轮的重算。小预算无法保留完整联合状态，频繁淘汰后回退重算。低复用没有 Host 命中，仍付出写出流量和 Host 占用，应结合实际复用率决定是否启用。
