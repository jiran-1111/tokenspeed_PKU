## 同输入MHA重放

`results/raw/homework1_mha_replay_20261014/`保存HF layer3输入下的重放。HF decoder输出精确复现原捕获；engine路径是同HF输入的反事实实验，不冒称它使用了原engine layer3输入。input norm、Q/gate投影、Q norm及Q RoPE完全一致；packed K/V投影分别只有9/8个元素不同。

最初core relative-L2约0.00010917、门控后约0.00285664、输出投影后0.00483311。该初始对照的两套Q/K/V并非逐元素一致，因此不能把core差异归因到注意力算子。独立复审指出此限制后，补上`homework1_mha_cross_input_20261014/`的两套输入×两套实现交叉对照：

- 每一套固定Q/K/V下，HF SDPA与NPU BNSD FIA输出均262144/262144精确一致。
- 更换输入后，两种实现都出现相同的0.00010917差异；本样例支持输入漂移而非注意力实现差异。
- 分别对每套输入计算CPU FP32 oracle及其BF16舍入版本。两实现相对未舍入oracle约0.0017386；相对舍入oracle仍约0.001329。不能把未舍入对照误当作纯量化误差，也不能据此推导24层logits容差。

`homework1_mha_gate_ablation_20261014/`四条件受控实验精确复现原路径。仅在sigmoid后保留HF的BF16边界，输出relative-L2降至0.00039068；同时固定HF core则全输出精确一致。这是参考兼容性边界的因果证据，不证明原FP32融合门控数学错误。原共享算子及既有测试采用FP32融合语义，未据此修改所有平台的实现。

新候选BF16门控测试出现2项BF16失败、1项FP32通过。为避免把未批准的新兼容性合同强加给标准回归，该新测试移至上述raw目录；原测试源与RED XML均保留。没有删除用户原有测试，也没有将失败改成通过。

## 卷积精度边界

`homework1_conv_precision_probe_20261014/`说明：HF原始卷积、runtime无激活卷积及CPU FP32点积后BF16舍入三者786432/786432精确一致；分离执行BF16 SiLU也与HF精确一致。runtime融合SiLU的relative-L2约0.00286872，与FP32点积后直接SiLU的结果接近，差异来自中间舍入边界。

BF16乘积先舍入再FP32求和的候选反而偏离HF，且不等于BF16累加器。没有证据支持修改卷积累加精度。18个A_log和18个dt_bias检查值均可精确用BF16表示，也未据此改权重加载。
