【第 3 次作业｜CKPT-3】存储子系统：分层缓存与 Host Offloading

同学们好，在模型计算与双 chip 并行正确运行的基础上，第三阶段研究有限 HBM 容量下的缓存管理，理解存储容量、数据搬运与推理性能之间的关系。

**课程目标：**掌握分层存储、缓存生命周期和数据一致性管理方法，能够分析缓存容量收益与传输代价。

**阶段目标：实现 HBM—Host 内存分层缓存，支持推理缓存卸载、设备空间回收及按需恢复。**

**时间：2026 年 11 月 11 日—11 月 26 日，共 2 周。**

### 任务要求

1. **打通分层缓存。**在 [TokenSpeed](https://github.com/lightseekorg/tokenspeed) 已有缓存框架上完成 Ascend 适配，实现类似 SGLang HiCache 的核心能力：保存缓存到 Host，在安全时机回收相应 HBM 空间，并在需要时恢复复用。
2. **保证状态正确。**梳理 Attention KV Cache、递归状态和卷积状态，说明各类状态如何保存、恢复或重算，保证恢复后能够正确继续推理。
3. **实现容量管理。**支持配置 Host 缓存预算，处理淘汰、未命中和多会话隔离，并与调度器的资源生命周期衔接。
4. **评估收益与代价。**比较开启和关闭 Offloading 时的 HBM 占用、Host 内存占用、数据搬运量、恢复延迟和吞吐，说明适用条件。

本阶段要求实现两级缓存的核心闭环，不要求完整复刻 HiCache。异步预取、分层加载、传输与计算重叠等可作为扩展方向。

### 实施与实验要求

**描述缓存生命周期。**说明缓存的标识、分配、可卸载条件、Host 存储位置、恢复时机与淘汰策略。明确正在使用或传输中的缓存何时可释放，如何避免覆盖尚未完成传输的数据，以及 Host 未命中时如何继续执行。

**明确混合状态的恢复边界。**列出 Attention KV、递归状态和卷积状态各自的保存粒度、对应上下文位置和恢复方式。若恢复快照后需要重算一段上下文，应准确记录恢复位置和重算范围，并将重算耗时计入结果。TP=2 下须保证各 rank 对恢复的上下文位置达成一致。

**建立容量与行为统计。**至少记录设备缓存已用与可用块、Host 缓存占用、卸载及恢复字节数、命中与未命中次数、淘汰次数和传输耗时。HBM 回收可以表现为缓存块重新可供调度器分配；若底层使用预分配内存池，设备监控工具的总占用不下降也可能是正常现象，应提供块级统计及实际复用证据。

**覆盖以下功能测试：**

- 卸载后恢复同一会话，结果与参考执行符合正确性判据；
- 多个会话交替运行，不发生缓存或状态串用；
- Host 预算不足时发生淘汰，后续请求能通过未命中处理正常执行；
- 同一缓存重复卸载、恢复或复用，不出现错误释放和持续资源泄漏；
- TP=2 下两个 rank 均完成必要状态处理，恢复后继续推理正确。

**开展容量与性能对照。**在相同设备缓存预算下比较“关闭 Offloading”和“开启 Offloading”，至少覆盖高复用与低复用两类访问模式，并改变一次 Host 缓存预算。关闭 Offloading 无法容纳同样工作集时，应记录失败或重算行为，另选双方均能运行的配置进行公平延迟对比。

### 阶段完成目标与进度检查

到 **11 月 26 日**，应具备以下能力：

- 在系统内完成实际缓存卸载、设备缓存空间回收及按需恢复；
- 通过正常恢复、缓存淘汰、多会话隔离等正确性测试；
- 至少在 0.8B 和一个较大模型上完成端到端验证，并覆盖 TP=2；
- 用已有统计解释容量收益、数据搬运与必要重算的代价。
