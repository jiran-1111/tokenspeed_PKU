本记录补充原4B/9B失败输入的独立全模型对照。[完整数据与工具](../evidence/homework2_20261028_e2e/README.md)。部署核心保持1531项`2a1a2196...`，未修改原输入、续接、失败或阈值，未运行新NPU实验。

## 补齐了什么

此前逐层数学参考使用部署实际中间操作数，不能替代独立全模型。新NumPy CPU程序只读原checkpoint和原IDs，自行完成embedding、32层、最终规范化、词表输出及全部因果历史。原128行Prefill加17/9次单行Decode，两模型各跑TP1/TP2模拟及BF16/FP32控制，共8组、112个完整向量；对应两模型各一条固定轨迹，共用同一个独特128-token Prefill输入。

BF16合同保留已确认的实际存储边界、Gemma有效gamma、FP32 SSM和9B FP32 head。参考的互补分片与求和在单个CPU进程中模拟，不是实际HCCL；NPU通信与状态映射依赖此前实测。FP32控制改变了参考存储精度，不能替代原BF16部署验收。

服务器31项软件测试通过/零skip，包含独立HF tiny完整模型和Torch eager BF16 RoPE对照；比较约束另7项通过/零skip。只有完整八组及全部身份核对成功后，才打开R3部署捕获作比较。工具manifest分别为`cf09ecac218c32702b757b6010f70b3f80125cc18ffec19290827c9bf1e534af`和`8976fe1f432691c47bca9a4e6097c255d3ebee07a233b79fff9fc8f9ee5ff261`。

## 两种分叉的独立解释

9B末步独立BF16 TP1的25389/35378为16.749174/13.436477，TP2为17.452042/17.546274，分别选25389、35378，重现部署两侧选择；FP32控制两侧都选25389。这表明同类分叉无需TokenSpeed或真实通信错误也能出现，支持低精度及分片扰动传播解释，不能证明所有部署残差可接受。

4B末步独立BF16两侧198/271均21.25，canonical均选198；部署TP1两者均21.125、选198，TP2为21.125/21.25、唯一最大是271。参考并列导致canonical不能唯一判断两个候选的优劣，**并不意味着部署TP2只是采用另一种tie-break规则**。零epsilon诊断显示实际选择落在对应参考精确最大集合，但不替代原canonical失败，亦未建立新验收门槛。FP32控制与HF CPU都唯一选271，间隔约0.02255。

## 身份、复核与结论

原参考53文件/约1.208 GB、分析16文件/约227 MB均取回工作区并逐项SHA匹配。比较器启动前和结束后5项工具SHA、启动源/客户端凭证摘要及最终summary绑定通过；这不是完整PID/starttick历史链。1531项核心后验保持，全部首层输入与独立checkpoint embedding逐元素相同。

本地独立重算20272组完整logits/末行norm/独立参考全行norm指标，并重核768个自身状态载荷，最大计算指标浮点差3.276e-15。该容差用于公式计算重现，不是模型通过阈值；本地没有重新提取原NPU PT。原始全128/1行实际边界、两rank状态和所有非零误差均保留在完整分析中。

本次已完成“从原始输入自行传播”的独立对照，补齐上一轮具体证据缺口。数值敏感性的证据更强，但实际BF16向量对独立BF16仍有明显差异，不能宣布原误差全部可接受或四模型全部数值通过；没有确认可直接采用的部署错误修正。任务二的比较与独立分析材料完成，数值验收结论继续有保留。任何后续部署数学修改仍须另固定源码，并做对应原样例与受影响性能复验。
