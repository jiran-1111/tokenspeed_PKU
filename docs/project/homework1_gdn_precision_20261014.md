## 全模型假设检查与保护

下一步只以临时opt-in hook测试这些边界对完整Prefill向量的影响：仅在位置127/ID271 guard armed时触发，保留逐阶段调用记录；未armed的启动/预热仍走原路径。不涉及持续Decode，因此不能推广到Decode或多模型验收。生产源保持原样，旧性能及失败合同仍保留。

SSH在消融完成及复制期间出现connection reset。通过远端完整comparison与8个数组、进程终态和NPU无进程确认实验已经完成，没有因连接退出1而重跑或覆盖。远端数据校验/跨端复制仍分别核验，不把SSH失败掩盖为实验已通过，也不把连接失败写成kernel错误。

实际全模型假设检查已完成一次native128/max1请求，目录`results/raw/homework1_precision_match_20261014`：54条标记恰好为18次conv BF16中间边界、18次Q/K+beta边界、18次gated norm边界，证明所有18个GDN模块实际触发。最大logit差0.23828125、relative-L2=0.0169668943（原0.0241289008），仍未通过1%合同；argmax仍8160，HF为71093。临时conv方案是在原runtime卷积无activation输出后施加BF16 SiLU，并没有替换整个卷积为HF算子，因此不等同于单层干预中直接替换HF卷积结果。暂不据此改生产实现或宣告根因闭环。

剩余候选有源码依据：实际NPU `SiluAndMul.forward_native`把gate/up扩展FP32，SiLU与乘法融合后只存一次BF16；HF MLP在SiLU后有BF16边界。MHA sigmoid-multiply也存在类似融合，但尚未进行受控重放，不能当已证实贡献。后续先用同输入/权重重放MLP及必要的MHA门控，再做单变量全模型假设检查；FP32 recurrent state不因模拟HF中间舍入而改为BF16。

同输入MLP重放已经完成，目录`results/raw/homework1_mlp_rounding_20261014`：分别使用已保存的HF/engine post-attention norm输入，原两条对应路径均复现各自整模型记录exact。对每一种相同输入，原NPU融合FP32激活与HF输出L2分别0.00352509/0.00349397；仅把SiLU输出按BF16边界舍入再乘up，两种输入均131072/131072 exact到HF输出。该局部因果证据支持进一步完整Prefill临时诊断，不代表已修正生产、连续Decode或其他模型。

再增加MLP边界的完整Prefill诊断完成，目录`results/raw/homework1_precision_match_mlp_20261014`：原三种标记各18次、MLP标记24次，78次调用全部确认。输出ID已改为HF相同的71093，但完整向量relative-L2=0.0166451968、max-abs0.234375，仍不通过1%合同。这说明输出ID对齐不能代替向量误差验收，也说明同输入单层MLP改善不能简单累计外推为整模型改善。后续继续排查剩余边界/注意力数值，不直接将当前临时方案改成生产默认。
