# 作业2补充诊断：9B实际缓存Decode第8步

本记录补充[作业2报告](../report/homework2_communication_subsystem.md)和[FA7 Prefill观察](homework2_fa7_diagnosis_20261025.md)。**原4B/9B短输入自由生成差异仍未修复；本次没有新增通过阈值，也没有改变主报告结论。** 结果限于原9B固定短输入的一个缓存步骤，不能推广为四模型或全模型正确性通过。

## 固定协议与实际采集

保持1531项核心运行源及清单SHA `2a1a2196dba54928cc0bde375eb8412df0c222f8cf98cf4ff94c9f66c13f2af3`。使用原128个输入ID及原9-token固定续接，Prefill记作step0，第8次缓存forward的实际输入位置为135，含当前token的有效前缀为136。仍走eager实际缓存路径，BF16、SSM状态FP32及原9B head FP32配置均未变。

额外观察器只保存该步骤FA7的有效KV、GDN层8–10的真实输入/输出状态，以及相关模块操作数；没有用重算prefix替代历史缓存，也不向运行状态写入参考结果。KV按真实页表恢复：写入前仅保存135行已定义历史，写入后保存136行。GDN按后端实际state-in/state-out索引各自选槽，卷积状态为BF16 `[C,3]`，递推状态为FP32 `[Hv,V,K]`，不假定物理槽跨rank相同。

运行时没有暴露请求ID，材料明确记录不可取得；通过同次forward的原case、实际输入ID、位置、step、单请求batch和FA序列长度绑定观察范围，没有虚构请求标识。共享RoPE与GDN类方法的观察器均限定目标层，先按原dtype复制再调用后续原地操作，并在结束或异常时恢复。

两项硬件采集串行运行：TP1使用card0/chip1，TP2使用同卡chip0/1。每项前重新核验设备映射、进程身份及余量；保留其他服务，原独占队列继续暂停。两项均exit0、自身上下文释放，保护记录没有违规。观察器影响耗时，故本批不作为性能数据。

TP1 rank0与TP2 rank0/1各保留原10个完整logits；**共30个向量相对上次同源FA7采集逐位一致**，实际输入前沿、位置、原始argmax和采样/固定续接决定也相同。这验证观察器对这些已测结果的保持性，不证明自由输出一致。

## 真实KV与单步运算参考

各CPU FP32参考使用该算子自己抓取的真实操作数。递推使用实际卷积输出及更新前SSM，不把CPU重算卷积输出继续传入；BF16候选只对FP32结果作最终存储舍入，不冒称模拟所有内核中间舍入。

| 检查范围 | 实际观察 |
| --- | --- |
| 三份rank的FA7 KV历史135行 | 本步前后逐位不变 |
| 三份rank的当前K/V | 写入后末行与本次实际输入逐位一致 |
| 使用真实136行KV的GQA attention | 相对自身FP32参考relative-L2为0.00165742–0.00172483；最终BF16候选仍有差异 |
| 九组GDN卷积输出及历史移位 | 输出与FP32最终BF16舍入候选逐位一致，更新后卷积状态逐位一致 |
| 九组GDN递推输出 | 相对自身FP32参考relative-L2为0.00131187–0.00234175；最终BF16候选仍有4/24576个元素不同，最大绝对差1.49011612e-8 |
| 九组更新后FP32 SSM | relative-L2为2.40018099e-8–1.00253295e-7，最大绝对差1.34110451e-7；没有宣称逐位一致 |
| 八个行投影SUM边界、两个TP2 rank返回值 | 16次比较均等于实际BF16部分和用FP32相加再按实际返回dtype舍入 |
| 三份rank、九个hidden norm边界的残差相加 | 27次存储舍入比较逐位一致 |

递推最终BF16候选的非零项为TP1层9的1元素、层10的2元素及TP2 rank1层8的1元素，其余六组逐位一致。hidden norm最终舍入候选也不是全相同：TP2两rank的层10 post-attention norm各有1元素不同，relative-L2为4.50742734e-5，最大绝对差0.001953125。这些例外完整保留。

以上结果限制了“本步历史被覆盖、当前KV写错、被测SUM合成错误”的解释，但没有为整段历史建立独立prefix oracle。TP1与TP2的历史本来已经不同：FA7更新前K/V跨TP误差分别为0.01037362/0.01168533，GDN8–10更新前SSM分别为0.00825274/0.00989778/0.01485158。局部参考接近不能证明所有历史状态正确。

## 输入与历史的CPU交叉替换

先逐位核对TP2的A_log、dt_bias与TP1对应value-head分片，并按Q/K/V逻辑段核对卷积权重。三层均匹配，才计算以下四组FP32结果。这是**跨TP参数身份相同**，不等于本批另做了checkpoint独立认证。

- Y1：TP1当前真实q/k/v/a/b与TP1更新前SSM。
- Y2：两个TP2 rank各自真实当前输入与自身更新前SSM，结果按value-head重组。
- 只换历史：TP1当前输入按head切片，配TP2更新前SSM。
- 只换当前输入：TP2当前输入，配TP1对应head的更新前SSM。

下表为各组输出相对Y1的relative-L2；实际NPU一列以实际TP1输出为分母，故它与CPU列的分母略有不同。没有新增阈值。

| GDN层（0起） | 实际NPU TP2/TP1 | CPU Y2/Y1 | 只换历史/Y1 | 只换当前输入/Y1 |
| --- | --- | --- | --- | --- |
| 8 | 0.09968584 | 0.09967065 | 0.00418349 | 0.09951300 |

在这个步骤，独立CPU数学用两侧已经分叉的操作数，也重现了与实际跨TP相近的递推输出差异；只换当前输入的结果接近同时换输入和历史的结果。由此应优先检查当前隐藏向量经投影、门控和规范化的传播，而不是直接认定本步SSM槽错配。这个替换包含非线性交互，不能把两列相加、换算成原因贡献百分比，或据此断言历史无影响。

对应跨TP hidden norm差异从FA7入口的0.00880967，变为GDN8/9/10入口的0.03811452/0.12683243/0.24467988；mixed-QKV差异为0.10489153/0.28937182/0.50245521。被测SUM正确并不要求单双chip相等：两个rank规约之前的部分结果，其输入已经不同，BF16分片计算也会改变舍入。

## 可复现材料与后续范围
