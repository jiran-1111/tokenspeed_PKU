# 四模型原生Agent独立Session复用性能实验

四模型各192条正式请求、64条预热请求全部通过固定实际输出IDs、历史与context检查，共768条正式请求和256条预热。Session复用与完整历史重算分为独立性能臂，没有同时运行质量控制请求。以下结果均来自修复版R9r2；r1三模型另存，不混入主结果。

## 源码、协议与质量边界

1409项源码清单SHA `2c9e47616eb3c460a740e2542e776ab655934a9ad7ed0ac0c1401a008a97d712`；协议SHA `c9bdb5b7e6f5d766a1f862b499410c97ba6019e51a5d46139b0186525d0259af`。四模型全部在同一实现上串行运行，每次重新检查逻辑/物理设备映射和所需chip空闲；0.8B/4B为BF16 TP1基线，9B为显式FP32输出头候选TP1，27B为BF16 TP2基线。服务器课程集合637通过/零skip，本机603通过/34项因无Torch跳过，运行前完整pre-commit round4通过。

参考是R8已经真实生成且经过完整实际历史重算匹配的固定轨迹。每模型2会话×16轮×8输出，Session-0第8轮前执行求和465并等待2秒，结果由脚本注入；它不是模型自主选择工具。Session ON只提交增量suffix并保留当前前沿；OFF每次提交完整历史。两臂每次都真实生成并严格匹配参考IDs，出现分叉即失败，不把强制token当成功。该实验支持这组轨迹上的条件重放正确性，不替代CPU数值验证、任意输入语义质量或统一课程评测。

同一Engine内，先各完整预热一臂，再按ON/OFF、OFF/ON、ON/OFF做三轮配对。每臂32请求及2秒工具等待全部计入wall；创建/关闭Session、停止采样与Engine启动不计入。每臂关闭两会话后要求active归零，采样停止并join后才退出Engine。OMP线程为1，主机affinity和时钟实现/分辨率保存在原始run中。

## 资源与解释

Prometheus六项池计数独立约0.25秒采样；HBM通过独立npu-smi查询，查询结束后等待1秒。原始表和查询起止时间均保留，分析器独立重解析双chip表并排除进程行。全运行HBM峰值包括预热和臂间阶段；单臂峰值仅使用起止均在臂内的查询，没有覆盖时记null，不记0。它们均是观察到的已用HBM，不是瞬时峰值或仅KV占用，不能据此推断Session ON必然减少整池预分配HBM。查询延迟、请求排队与冷/热状态会影响分布。实验保护其他用户任务，目标chip空闲检查不等于整机独占；主机/其他设备背景负载未随机化隔离。未测HCCL子阶段，不编造通信归因。

收益支持当前有限Agent轨迹采用原生Session复用。OFF明确关闭prefix cache，比较代表当前系统全历史重算路径，不能外推为相对于其他引擎所有缓存策略的优势。9B头精度是固定条件；其精度与Decode/HBM代价另见[R5头精度消融](9b_lm_head_precision_20261015.md)，该旧消融不冒称本轮同源测量。0.8B原始greedy差异、HW1旧1%失败仍独立报告，不用本轮Session输出一致替代。

## 修复、留档与复现

独立只读审查发现坏chunk导致剩余流未排空、第二个Session创建失败泄漏第一个Session两项P2；新增三个回归先RED再GREEN，专项21项通过，审查复核仅覆盖修复范围。修复前r1的0.8B/4B/9B正常路径数据全部保留。为满足最终同源要求，r2固定源码后四模型完整重采；协议、轨迹、阈值均未按结果修改，也未按性能挑选重跑。

四模型均退出0，逐项源码后验零差异，所用chip退出后空闲。所有原始归档跨端逐文件SHA核对，本机独立分析与服务器JSON语义一致；分析器还用已知合成时序与故意坏输出做自检，合成数据不混入硬件结果。见[公开证据与精确复现说明](../evidence/native_performance_20261018/README.md)。本轮属于课程项目阶段交付，TP候选、最终配置的同源验证、总报告与答辩材料按收尾计划继续，不宣称全项目已验收。

一次本机最终复验把临时目录设在隔离仓库外，触发既有路径保护（1 failed/4 errors）；修正为仓库内新目录后603通过/34 skip，失败日志保留，未修改实现或测试门槛。
