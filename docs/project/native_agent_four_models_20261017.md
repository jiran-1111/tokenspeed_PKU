## 同源并发对照的新观测

在同R8源码、同输入和0.1秒独立采样下，再运行一次`concurrent`控制时序：32组输出/context通过、工具窗口综合判据也通过，窗口内另一Session完成1轮、19个正活动块样本、恢复复用715 tokens。该次所有32组输入/输出与R7及R8 afterrun均完全相同，没有删选重跑。第8轮原生请求在工具前0.007s开始、工具后1.454s完成；第9轮在1.455s开始、4.349s完成。窗口内完整“开始且结束”的请求数为0，原判据要求窗口内完成，未提高或放宽该判据。

因此R7的负结果不能仅由“存在并发质量重算”解释，本次也不能单独证明控制时序改变是唯一原因。缓存/编译热度及运行时序没有在这个额外单点中反平衡控制；其完成轮数1与afterrun的7不能当作独立性能收益。两个新点与旧失败均保留，后续性能须固定协议、预热及重复次序另测。

LCM计数是引擎池内parent块计数；TP多rank按既有端点汇总口径解释。idle持页和工具恢复复用共同支持本协议中的Session留存，关闭后active=0表示活动引用解除；cached/allocated仍可非零，不能说预分配HBM已释放给系统。工具窗口采样独立于请求完成回调，保留真实时间戳，非每个Session独立的块归属追踪。

这组验证没有独立OFF/ON性能臂。把质量控制移到执行阶段外会改变竞争负载，不能据此声称系统加速；原生/重算阶段时长也不是可比较的吞吐收益。有限32组配对不构成任意输入语义质量或完整课程项目验收；TP匹配性能、消融、最终配置/总报告与答辩继续完成。
